# 笺 · 重构总规划（v0.6.0 → v1.0）

> Lead 的决策文档。所有人以此为准；与它冲突的个人品味让步。
> 现行约定见 `docs/ENG-CONVENTIONS.md`，架构事实与踩过的坑见 `docs/HANDOVER.md`。

## 一、这次重构的判断

现有版本（0.5.24）的**骨架是对的**：纸感 + 印章的视觉母题立住了，三个模块的判定引擎
有真实内容（Lab 色差、菜库 + 忌口推演、聊天文本结构化），测试门禁 1200+ 断言。
但它停在「一个能用的 demo」：

1. **体量不够**：三个模块各只有一个动作（过笺 / 排桌 / 捞笺），做完就没事干了。
2. **没有「明天还回来」的理由**：没有记录、没有积累、没有统计、没有成就、没有提醒。
3. **动线断**：衣笺判完不进衣橱统计，味笺排完不留菜单，言笺捞完不设提醒。
4. **「我的」是一张设置清单**：没有个人档案、没有偏好、没有主题、没有通知入口。
5. **原生能力只用了一半**：没有通知、没有分享接收、没有主题跟随、没有节日彩蛋。
6. **视觉有高光但不成体系**：报告页和空态很讲究，列表/表单/信息密度段还是普通灰盒子。

## 二、重构目标（验收口径）

> 一个陌生人装上 APK，能连续用两周每天都有新东西可做，
> 每一屏都像一本杂志的内页，且任何一次点击都不会落空。

- **模块**：三笺 → 五笺（衣、味、言、笺谱、册），底栏 5 个目的地
- **屏幕**：6 屏 → 20+ 屏（含子页/浮层）
- **可玩机制**：连续天数、成就徽章、年度总结、热力图、每日一问、节日彩蛋
- **数据**：新增 ~12 个 state 集合，全部有上限、有钳位、有迁移
- **原生**：本地通知、文本分享接收、主题跟随、启动图、快捷方式 4 条
- **质量**：`npm test` 全绿、`npm run test:e2e` 全绿、模拟器逐屏截图复核
- **交付**：签名 APK + AAB + 更新后的 README/ROADMAP/NEXT

## 三、阶段划分（并行 lane）

### Phase 0 · Lead 打地基（串行，其他人等）

1. `state.js` 加全部新集合并钳位（一次加完，避免后来者反复改）
2. `index.html` 加新屏幕骨架 + 新脚本位
3. `styles.css` 加暗色主题变量、新组件基类
4. `ui.js` 加导航重构（5 项底栏 + 二级页返回栈）
5. `theme.js` 新文件：亮/暗/自动 + 字号 + 动效
6. `icons` 补齐

| lane | 文件 | 交付 |

| Y（衣笺） | `yi.js` + `wardrobe.js` + `styles-yi.css` | 单品完整档案（价格/购入日/品牌/尺码/场合/季节）、CPW 单次穿着成本、穿着日历、搭配册、愿望单冷静期、购物统计 |

### Phase 2 · Lead 集成与门禁

- 补 e2e 新节（100+）
- 修 `dead_controls` / `contrast` / `perf` 新失败
- 出包、模拟器逐屏验收

### Phase 3 · 收尾

- 文档重写（README / ROADMAP / NEXT / 交接说明）
- 商店材料更新
- 截图成品集

## 四、明确不做（产品判断）

- 不做社交 Feed / 评论 / 关注（微信个人主体做不了，且会毁品牌）
- 不做电商/商城/试穿
- 不做账号体系（数据只在本机是卖点，隐私政策已承诺）
- 不做真实支付（演示订阅保留，文案说清）
- 不做多语言（中文单语，把中文做到最好）
- 不做横屏/平板版式（一张竖着的纸）

## 五、可玩性的六条抓手（每一屏都要能回答「为什么明天还来」）

1. **积累感**：衣橱 CPW 下降、味笺做过多少道菜、言笺办掉多少件事 —— 屏幕上有数字在长。
2. **连续感**：连续使用天数、每周回顾、月度小结 —— 断了会心疼。
3. **意外感**：每日一问、随机推荐、今天适合穿什么、节日彩蛋。
4. **产出物**：报告长图、年度总结长图、菜单长图、成就卡片 —— 能发出去。
5. **掌控感**：搜索、筛选、排序、批量、撤销 —— 东西多了也找得到。
6. **惊喜**：成就解锁、隐藏印章、彩蛋文案 —— 不弹窗、不喧哗，藏在细节里。
