# 「笺」双端打包指南（Android APK / iOS）

> 本指南记录把「笺」H5 打包成原生 App 的完整流程。Web 层用 [Capacitor](https://capacitorjs.com/)（当前 8.x）套壳，H5 源码保持零构建、零依赖，`www/` 与 `android/` 均为生成物，源码仍是根目录那几个文件。

## 0. 工程结构与前提

```
jian/
├── index.html / styles.css / config.js / engine.js / api.js / app.js / manifest.json / icons/   ← H5 源码（唯一要维护的代码）
├── scripts/build-www.mjs      ← 白名单复制 H5 → www/
├── scripts/generate-icons.py  ← Pillow 手动生成 Android 图标（@capacitor/assets 的回退方案）
├── capacitor.config.json      ← Capacitor 配置（appId com.jian.app，webDir www）
├── assets/                    ← @capacitor/assets 的源图（icon.png 1024、icon-source.png）
├── www/                       ← 构建产物（npm run build-www 生成，勿手改，已 gitignore）
├── android/                   ← cap add android 生成的原生工程（源码进版本库）
└── node_modules/
```

本机要求（Windows 已验证）：
- Node ≥ 20（本机 24.20）
- **JDK 21**：Capacitor 8 的 `capacitor-android` 模块 `sourceCompatibility = JavaVersion.VERSION_21`，JDK 17 编译会直接失败。本机用 Temurin 21 zip 免安装版解压在 `C:\Users\11930\jdk-21.0.12.1+1`，并通过 `android/gradle.properties` 的 `org.gradle.java.home` 指定。**换机器时改这行路径，或干脆删掉该行并设置 `JAVA_HOME` 指向任意 JDK 21。**
- Android SDK（含 platforms、build-tools、platform-tools；`android/local.properties` 的 `sdk.dir` 指向 SDK 根目录，注意 properties 文件里 `\` 要写成 `\\`、`C:` 的冒号写成 `C\:`）
- licenses 已接受；没接受就 `sdkmanager --licenses`

关键一步（所有平台通用）：

```bash
npm install              # 装 @capacitor/* 全家桶
npm run build-www        # 白名单复制 H5 到 www/（sw.js 存在才复制）
```

## 1. Android：从 clone 到 APK（本机已验证）

### 1.1 Debug APK

```bash
git clone <repo> jian && cd jian
npm install
npm run android
# 等价于：npm run build-www && npx cap sync android && cd android && cmd /c gradlew.bat assembleDebug
```

Git Bash 里直接跑 gradle 的写法（任选其一，均已验证可执行）：

```bash
cd android && cmd //c "gradlew.bat assembleDebug"   # Git Bash 推荐
cd android && sh gradlew.bat assembleDebug          # 也可以
cd android && ./gradlew assembleDebug               # 若装了 Perl/POSIX 兼容层
```

产物：

```
android/app/build/outputs/apk/debug/app-debug.apk
```

装到真机：`adb install -r android\app\build\outputs\apk\debug\app-debug.apk`（adb 在 `%LOCALAPPDATA%\Android\Sdk\platform-tools\`，不在 PATH 的话用全路径）。

### 1.2 Release 签名（正式包）——**已配置完成**

签名链路已经接好并真实出过一次签名包（apksigner 验证通过，非 debug 证书），日常直接用一条命令：

```bash
npm run release
# 等价于：npm run build-www && npx cap sync android && cd android && cmd /c gradlew.bat assembleRelease
# 产物：android/app/build/outputs/apk/release/app-release.apk
# 出 AAB（上架 Google Play 用）：cd android && cmd //c gradlew.bat bundleRelease
```

当前真实布局（**换机器或重装系统时，下面两样东西都要迁移**）：

1. **Keystore：`android/app/jian-release.keystore`**（alias `jian`，RSA 2048，有效期 10000 天，主体 `CN=Jian, OU=Jian, O=Jian, L=Beijing, C=CN`）。
   已加入 `.gitignore`，不进版本库——**务必备份此文件，丢了无法更新应用**（同一应用换签名证书后，已安装用户无法覆盖安装，应用商店也不允许换签名发更新）。备份时和密码一起存到密码管理器/私有网盘。
2. **签名密码：`C:\Users\11930\.gradle\gradle.properties`**（用户目录，不在仓库内、不进版本库），四个键：

   ```properties
   JIAN_STORE_FILE=jian-release.keystore
   JIAN_STORE_PASSWORD=<密码>
   JIAN_KEY_ALIAS=jian
   JIAN_KEY_PASSWORD=<密码>
   ```

   换机器时：把 keystore 放回 `android/app/jian-release.keystore`、把上面四行（含密码）写进新机器的 `~/.gradle/gradle.properties`，并按第 0 节改好 `org.gradle.java.home`，然后 `npm run release` 即可。

兜底行为（有意设计，写在 `android/app/build.gradle` 注释里）：`buildTypes.release` 的 `signingConfig` 用 `findProperty('JIAN_STORE_PASSWORD') != null` 判断——本机配置了签名属性就用 `signingConfigs.release` 正式签名；**没有任何机器都有该属性，缺属性时回落 debug 签名**，保证任何人 clone 后不做任何配置也能 `gradlew assembleRelease` 出一个可安装的 release 包（只是 debug 签名，不能用于正式发版）。`signingConfigs.release` 的四个属性也全部用 `findProperty()` 读并带空值兜底，缺属性不会导致脚本解析失败。

验签方式（确认是正式签名而非 debug）：

```bash
# apksigner 在 %LOCALAPPDATA%\Android\Sdk\build-tools\<版本>\
apksigner verify --print-certs android/app/build/outputs/apk/release/app-release.apk
# 正式签名输出：Signer #1 certificate DN: CN=Jian, OU=Jian, O=Jian, L=Beijing, C=CN
# debug 签名则是 CN=Android Debug,O=Android,C=US
```

版本号有**四处**要一致（当前 **0.5.6 / versionCode 9**）：`package.json`、`config.js` 的 `version`、
`android/app/build.gradle` 的 `defaultConfig`、以及 `sw.js` 的 `const VERSION`（离线缓存的名字带版本号，
它落后一版就等于老用户永远拿不到新壳）。界面上「我的」页脚只显示 `config.js` 那一处。

发版时 `versionCode` 加 1（Android 判断升级只看它），`versionName` 与另三处对齐。
`npm run build-www`（`android` / `release` 都会先跑它）会拿这四处对账，不一致直接停手不出包——
以前这里漂成过「界面写 0.5、gradle 是 0.5.1、文档说 0.4.0」。

### 1.3 日常改完 H5 怎么同步

```bash
npm run cap:sync     # build-www + cap sync android（复制 web 资源、更新插件）
cd android && cmd //c gradlew.bat assembleDebug
```

只改了 H5 文件时不需要**手改** android/ 里任何东西，但 `npx cap sync` 这一步不能省：
它把 `www/` 拷进 `android/app/src/main/assets/public/`，安卓跑的就是那份拷贝。
直接在 `android/` 里敲 `gradlew` 而没先 sync，打出来的包跑的是**上一版前端**，而所有测试都是绿的
——拆成多文件之后这里就还停在 0.5.1 的单包 `app.js`。
`npm run check` 现在会盯这一处（清单同样从 `build-www.mjs` 白名单读，与 `www/` 逐字节对账）。

### 1.4 出完包之后验什么（release 是唯一过 R8 的那个包）

`release` 开着 `minifyEnabled` + `shrinkResources`（AGP 8.14.3 + JDK 21）。它的风险不是编不过，
而是「编过了、装上了、某个东西静默没了」：Capacitor 的插件靠注解 + 反射注册，
`drawable/splash`、`mipmap/*` 又是拿名字去查的（`AssetUtil.getIdentifier`），裁剪器看不见这种引用。
所以钉了 `res/raw/keep.xml`，并且**release 包必须被真的装起来看一眼**——它没有 CDP
（`webContentsDebuggingEnabled` 跟随 `isDebug`），`device_verify.py` 那套对它完全无效。

```bash
cd android && cmd //c gradlew.bat assembleRelease assembleDebug bundleRelease
python test/release_smoke.py       # 装 release → 验签名/真的画出界面/无崩溃 → 装回 debug
python test/device_verify.py       # 桥与行为 + 冷启动还在不在（32 项，要 debug 包）
python test/device_deeplink.py     # 快捷方式 / 深链 / 夜间模式的纸色（21 项）
python test/device_perf.py         # 设备侧帧耗时基线（18 项；卡帧率只打印，见下）
npm run test:pkg                   # www / 安卓资产 / sw 清单 / 载荷重量 / 快捷方式三头对得上 / APK+AAB 里是哪版前端
```

**这四套不需要再手写 `ANDROID_SERIAL=`**。它们开工第一件事是认领串口
（`test/device_avd.py` 的 `require_avd()`）：在线的只有一台、而且 `adb emu avd name`
回的是 **`jian_test`** 才继续；不是就退出并把该怎么做写清楚。
带上了 `ANDROID_SERIAL` 也只是**少问一次 `adb devices`**，名字那一关照样要过——
环境变量是一张待核实的地址，不是通行证。细节见 `docs/安卓自验指南.md` §6。

`release_smoke.py` 看的是像素：屏幕上有没有墨色文字（界面真画出来了）、纸色占大头（不是黑屏白屏）、
印章红还在（图标与印色资源没被裁光），外加 logcat 里不许有 FATAL / NoClassDefFoundError。
它跑完会把 debug 包装回去（release 与 debug 签名不同，不能覆盖安装，所以脚本里先 uninstall）。

`device_deeplink.py` 补的是**只有设备能答的三件事**：
1. `am start -a VIEW -d jian://screen/yan` 真能把 App 开到言笺（冷启动、热启动、模块被关掉三条路），
   并且热启动**不是重载整页**（判据：页面里预先埋的 `window.__warm` 还在）；
2. `dumpsys shortcut` 里那三枚静态快捷方式确实被系统注册了、标签取到了中文、指向 MainActivity；
3. 系统夜间模式下**纸还是纸**：整屏主色 `(244,239,230)`，与亮色模式逐通道一致。
   顺带把「反色」这件事量清楚了：把 `android:forceDarkAllowed` 和 CSS 的 `color-scheme: light`
   两个都去掉重装一次，夜间模式下纸**仍然没被反色**（WebView 124 / API 35 实测）。
   所以那两行是保险，不是修好的 bug——真正需要 `color-scheme` 的是 UA 控件的皮肤，
   那条由 e2e 第 23 节在浏览器里钉住（`emulate_media(color_scheme='dark')` 之后纸底与输入框颜色不许变）。

`device_perf.py` 里 **卡帧率只打印不设预算**：同一套节奏下量系统桌面 `com.android.launcher3` 是
59 帧 / 88.14% janky（对照实验），这台 AVD 的合成器给不出「不卡」的帧，拿它当门只会永远红。
可信的是八项 JS 侧耗时（换屏中位 14ms、36 件重绘 2.4ms、200 条言笺 10.4ms、排一桌 10.8ms）。
另两个坑：JS 里连切 24 次屏合成器只画一两帧（要按人手节奏铺开）；`saveCard()` 在原生壳里会拉起
系统分享面板，`await` 不返回还会把 gfxinfo 数脏，所以量的是 `drawCardStyle` / `drawMagStyle`。

开机前先 `adb devices`：踩过一次自己起了**两个** jian_test（5554 与 5556），两个模拟器抢 CPU，
设备套件里就出一条说不清的抖动红；查归属用 `adb -s <serial> emu avd name`（权威），别看端口猜。

**跑完这一轮就要关机**：`adb -s emulator-5554 emu kill`，再确认 `adb devices` 里没有 5554、
`tasklist` 里没有对应的 qemu（AGENTS.md 的硬约束；空闲模拟器不会把内存还给系统）。

0.5.2 这一轮的实测数字：release APK **4.95MB → 1.42MB**、AAB **4.50MB → 1.89MB**
（其中去掉 2.9MB 冗余启动图 + 272KB 出图源图，其余是 R8 与资源裁剪）；`res/` 3.2MB → 254KB；`www/` 562KB → 245KB。

bundletool 的可执行 jar 这台机器取不到（Maven 上没有 `bundletool-all`，只有不带主清单的库 jar），
所以 AAB 用 `npm run test:pkg` 直接解开比对：`base/assets/public/*` 与 `www/` 逐字节一致、
且没有多余的旧文件——这条才是真正会出事的地方（包里躺着上一版前端）。

## 2. iOS：构建只能在 macOS 上做

**先更正一句旧结论**：`npx cap add ios` 本身不检查操作系统（`@capacitor/cli/dist/ios/add.js` 只是解模板），
`cap sync ios` 在没有 CocoaPods 时也只是提示「Skipping pod install because CocoaPods is not installed」。
所以 **iOS 工程可以在 Windows 上生成并提交进仓库**；真正做不了的是在 Windows 上构建——
Xcode、模拟器、签名、`.xcframework` 链接、上传 App Store Connect 都必须有 macOS
（公开仓库可以白嫖 GitHub Actions 的 macOS runner）。目前本仓库仍未执行过 `cap add ios`，`ios/` 不存在。

Mac 上拿到本仓库后：

```bash
# 0) 前提：Xcode 15+（App Store 装）、CocoaPods（sudo gem install cocoapods）、Node 20+、JDK 不需要
# 1) 装依赖并生成 www/
npm install
npm run build-www

# 2) 生成 iOS 工程（会创建 ios/ 目录，首次还会 pod install）
npx cap add ios
npx cap sync ios

# 3) 打开工程
open ios/App/App.xcworkspace     # 注意是 .xcworkspace 不是 .xcodeproj

# 4) 在 Xcode 里：
#    - Signing & Capabilities：选 Team，改 Bundle Identifier（建议 com.jian.app.ios 或沿用 com.jian.app）
#    - General：App 名称「笺」已由 cap add 从 capacitor.config.json 带过去，核对版本号
#    - App Icons：把 assets/icon-source.png（512）导入 Assets.xcassets 的 AppIcon（Xcode 14+ 支持单张 1024 图直接拖入）

# 5) 运行
#    - 模拟器：Xcode 里选 iPhone 模拟器直接 ▶︎
#    - 真机：插 iPhone，选设备 ▶︎（首次要在 iPhone 上信任开发者证书）

# 6) 上架 App Store Connect：
#    - Xcode 菜单 Product → Archive
#    - Organizer 里 Distribute App → App Store Connect → Upload
#    - App Store Connect 后台建 App（Bundle ID 一致）→ 提交审核
#    - 或用 Transporter / xcrun altool 上传 .ipa
```

本仓库已经为 iOS 准备好的部分：
- `capacitor.config.json`（webDir、appId、appName、SplashScreen 插件配置——iOS 原生识别同一份配置）
- `www/` 构建链路（`npm run build-www` 跨平台，纯 Node）
- `assets/icon-source.png`（iOS AppIcon 的 1024 源图，从 icon-512 放大而来）
- 依赖里的 `@capacitor/status-bar`、`@capacitor/splash-screen` 都是双端插件，iOS 侧无需再装

## 3. 备选方案：PWABuilder 云打包（零本地环境）

若只是想快速拿个 APK 不配环境：

1. 把 H5 部署到 HTTPS 域名（PWA 要求安全上下文；本项目 manifest.json 已就绪）
2. 打开 <https://www.pwabuilder.com/>，输入线上 URL，点 Start
3. Package for stores → Android → 选 Signature 方案（可让 PWABuilder 代签或上传自己的 keystore）→ 下载 zip
4. zip 里有 `app-release-signed.apk`（直接装）、`assetlinks.json`（放到 `/.well-known/` 启用 TWA）

局限：TWA/WebView 打包对离线、文件下载等 Web 能力依赖线上服务，且图标/splash 规则与 Capacitor 工程不共用。正式发版建议仍走第 1 节的 Capacitor 工程。

## 4. 已知坑（都在本机踩过或已预案）

1. **`<a download>` 在 WebView 里不生效**。Android WebView 不支持原生下载行为，导出/保存文件要用已装好的两个插件：
   ```js
   import { Filesystem, Directory, Encoding } from '@capacitor/filesystem';
   import { Share } from '@capacitor/share';
   // 1) Filesystem.writeFile 写到 Directory.Cache / Documents
   // 2) Filesystem.getUri 拿 file:// 路径
   // 3) Share.share({ url: uri }) 拉起系统分享面板
   ```
   依赖已装（@capacitor/filesystem、@capacitor/share），`cap sync` 时会自动注册进 APK。判断环境：`Capacitor.isNativePlatform()`，H5 里保留 `<a download>` 原逻辑即可，原生分支走上面三步。
2. **safe-area（刘海/手势条遮挡）**。WebView 默认内容延伸到屏下；两种处理：
   - Android 11+ 的 `edge-to-edge` 显示时，给根容器加 `env(safe-area-inset-*)`（styles.css 里已按 PWA 规范可加）；
   - 或在 `capacitor.config.json` → `android` 段调 `adjustMarginsForEdgeToEdge`（Capacitor 8 提供 auto/force/never）。
3. **localStorage 持久性**。WebView 的 localStorage 在「用户清除应用数据」「系统存储空间紧张回收」「WebView 数据目录被清理」时会丢。要可靠存档就用已装的 `@capacitor/preferences`（底层是原生存储，不随 WebView 清理），迁移时把 engine.js 的读写抽一层按平台分流。
4. **JDK 版本**（本机踩过）：Capacitor 8 起强制 Java 21，JDK 17 报错形如 `error: invalid source release: 21` / `Unsupported class file major version`。解法见第 0 节。
5. **SDK 版本不匹配**：Capacitor 8 模板要 `platforms;android-36`，没有就 `sdkmanager "platforms;android-36" "build-tools;36.0.0"`，或把 `android/variables.gradle` 里 `compileSdkVersion/targetSdkVersion` 降到本机已有版本（targetSdk 不得高于 compileSdk）。
6. **国内网络加速**（本机踩过）：`services.gradle.org` 实测 ~30KB/s，已把 `android/gradle/wrapper/gradle-wrapper.properties` 的 distributionUrl 换成腾讯镜像 `https://mirrors.cloud.tencent.com/gradle/gradle-8.14.3-all.zip`；国外网络环境可改回官方地址。Gradle 依赖仓库默认 google()/mavenCentral() 一般可达，若也慢可在 `android/build.gradle` 的 repositories 里前置 `maven { url 'https://maven.aliyun.com/repository/google' }` 与 `.../public`。
7. **启动图（本轮重做，别再回到老路）**。以前 `@capacitor/assets` 按整屏铺一张 2732×2732 的 PNG，
   11 个密度/横竖屏目录各存一份 = **2.9MB 资源、解码 29MB 位图**，而且 `icons/splash-2732.png`
   还被 `build-www` 整目录拷进 `www/`，白送用户 272KB。现在：
   - `res/drawable/splash.xml` = 层叠图（纸底 `@color/splash_background` + 居中 `@drawable/splash_icon`），
     印那张小图由 `python scripts/generate-icons.py` 从 `icons/icon-maskable-512.png` 抠出来，五个密度各一张，共 43KB；
   - 同一支脚本还生成 `mipmap-*/ic_launcher_monochrome.png`（安卓 13+ 主题图标层，已进 `mipmap-anydpi-v26/*.xml`）；
   - 出图用的 2732 源图挪到了 `assets/splash.png`（不在 `icons/` 里，所以不会进 H5 载荷）；
   - **`npm run assets`（@capacitor/assets）会重新生成那 11 张大图，别再跑它**；
     `npm run test:pkg` 里有一条会当场抓住「res/ 又出现整屏 splash.png」。
   - 顺带：`android:windowBackground` 只能放**纯色**。放那张层叠图会让窗口被判定为半透明窗口，
     系统条那一条直接渲染成黑（实测顶条 128px 全黑）。
8. **状态栏图标必须显式说深色**。`@capacitor/status-bar` 的 `style` 默认 `DEFAULT`，
   而 DEFAULT 是**跟着系统夜间模式走**的（`StatusBar.getStyleForTheme`）——手机开深色模式，
   系统就给一副浅色图标，压在纸上直接看不见时间电量。`ui.js` 的 `paintNativeChrome()` 在 boot 里
   调 `setStyle({style:'LIGHT'})` 钉死。`setBackgroundColor` 在安卓 15+ 已经失效（强制 edge-to-edge），
   所以颜色交给窗口主题（`values/styles.xml` 里 statusBarColor / navigationBarColor / windowLightStatusBar）。
9. **竖屏是刻意的，上架要交豁免**。`AndroidManifest.xml` 里 `android:screenOrientation="portrait"`
   + `android:resizeableActivity="false"`。去掉锁试过：横屏时 WebView 仍按竖屏尺寸排版，
   左边一条空纸右边全黑。Play 对 targetSdk 36 的大屏/方向政策要求「要么支持，要么说明理由」，
   所以上架时在 Console 提交方向豁免，理由就是「一张竖着的纸，宽窗另有桌面版式（styles.css ≥900px）」。
10. **返回键**。`android:enableOnBackInvokedCallback="true"` 已开（安卓 16 起对 targetSdk 36 默认如此），
    App 插件用的是 AndroidX `OnBackPressedDispatcher`，行为是「先回上一张纸（衣笺报告 → 衣笺），
    栈底才退到后台」，逻辑在 `ui.js` 的 `goBack()`，e2e 第 18 节盯着它。
11. **拍照入口要 `<queries>` 才有效**。`<input type="file" accept="image/*" capture="environment">`
    在 Capacitor 里走 `onShowFileChooser` → `resolveActivity(ACTION_IMAGE_CAPTURE)`。
    安卓 11+ 有包可见性限制：清单里不写 `<queries><intent><action ...IMAGE_CAPTURE/></intent></queries>`，
    `resolveActivity` 对相机应用**一律返回 null**，Capacitor 只留一句
    `Media capture intent could not be launched` 就退回相册选择器——点「拍照」开的还是相册，
    而界面上一切正常。已补进清单，并在设备上跑通：真相机 → 拍 → ✓ → 回 App 出判定。
    同时加了 `<uses-feature android:name="android.hardware.camera" android:required="false">`，
    让没有相机的设备也装得上（拍照只是入口之一）。
12. **设备脚本只准动自己那台模拟器**。这台机器上多个会话共用一个 adb server，而且串口会漂
    （自己那台一退，别人的 AVD 可能马上顶到同一个 `emulator-5554`）。以前五套脚本都写着
    「环境变量没给就退回 5554」——忘了带就会把笺的包装到**别的项目的机器**上，跑完还报一句全绿。
    现在一律先过 `test/device_avd.py` 的 `require_avd()`：它 `adb emu avd name` 认到 **`jian_test`**
    才放行，并把串口写进 `ANDROID_SERIAL`（`cap-cdp` 里那句不带 `-s` 的 `adb shell pidof` 靠它）。
    这一条由 `test/device_guards.py`（45 项，桩掉 adb 问话，不碰真设备）钉住，已进 `npm run test:fast`。
    验证跑完就 `adb -s <你那台> emu kill`（AGENTS.md 的硬约束），
    **不要用 `adb kill-server`**——那会连带打断别的会话。
