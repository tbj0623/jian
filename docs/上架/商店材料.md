**上架前必须做的四件事**：
1. `versionCode` 从 5 往上加（Play 只认它判断升级），`versionName` 与 `package.json` / `config.js` / `sw.js` 一起对齐——
   `npm run build-www` 会拿四处对账，不一致就不给出包。
2. 走 Play App Signing（应用签名托管）时，用「上传密钥」而不是把 `jian-release.keystore` 交出去；
   如果选择**不自管签名**，一旦丢了 keystore 就永久无法更新这个包名。
3. `npm run test:ship` 绿一次：量「GitHub 上那一页 == 仓库里的源」，顺带实抓一次公开 URL。
   商店页引用的是那个 URL——网上留着旧的那一句，就是旧的承诺还挂在那里。
4. **应用内要能打开这份政策** —— 第 62 轮已经做掉了：「册」里「数据只在这台设备」那一句下面就有这条入口，
   网址本身写在屏上（不是一枚只写「隐私政策」的按钮）、能复制、也交给系统浏览器打开。
   那条 URL 在仓库里只有 `config.js` 一处定义，第 1 节这一格、政策页的 canonical、应用里这一份，
   三处由 `test/store_claims.py` 对账（改一处漏两处就红）。

**第 4 条与上面那三条的口径，来源要如实标注**：这台机器现在整个 Google 域不可达
（2026-09-24 实测两回：`curl` 与 `WebFetch` 到 `support.google.com` / `play.google.com` /
`developer.android.com` 全部超时，同一个工具抓 `example.com` 正常 200），所以关于 Play 政策的
三句结论**只做到「搜索索引确认官方页存在且标题相符」，没有逐字核对过原文**。它们是：
① `*.github.io` 可以用（找不到任何禁止条款，Google 侧只要求公开可直接访问、URL 直达正文）；
② 应用确实不收集数据时，政策可以直写「不收集」，Data safety 表也留了「不收集」这条路径；
③ 「账号删除要给一个网页链接」只适用于允许创建账号的应用——笺没有账号体系，按这条免除。
**这三条都按推断用，别当已核实**；能连上 Google 域的时候应当回来把这三句和出处逐字对一遍。

## 2. 文案（可直接粘贴）

**简短说明（80 字符内，实测 40）**

> 三张笺：买前问柜子、这桌能否入口、说过的话落成笺。零账号、零广告，不联网也能用。

「零联网」这个词在第十七轮之后就不能再写了：应用默认确实一个字都不发出去
（`config.js` 的 endpoint 是空的，判定全在本机规则引擎里算），但用户可以在「我的」里
填一台自己的网关，那时照片会离开设备——数据安全表已经如实写了这一条。
短说明要是还写「零联网」，就和那张表自相矛盾了；「不联网也能用」说的是同一件事，但是真话。

**完整说明（4000 字符内，实测 1143）**

> 笺是三张短笺，帮你在下单前、动筷前、答应前先把那一下想清楚。
>
> 衣笺 · 先问柜子
> 想买的衣服拍下来，笺去你已有的柜子里比：同品类有没有、色差多大、上次穿是什么时候。
> 它不劝你买，只把「你其实已经有了」这件事摆到你面前。柜子可以改名、改品类、改主色、按季节筛、
> 按名字搜，穿过的记一笔，久未穿的会提醒你——换季收起来的夏装不在此列。照片从相册挑，也可以现拍一张。
>
> 味笺 · 这桌能入口
> 菜单一行一道贴进来，或者干脆把群里那段话原样粘进来——笺分得清哪句是菜、哪句是安排。
> 说清这桌有谁、谁忌口，笺给出能不能入口、缺什么主料、荤素怎么配、先上什么，
> 以及一段可以直接发到群里的话。句子里写着的忌口它也真的拿去用：
> 「有人不吃辣」不会变成一道菜，而会让那盘辣子鸡进「有人不能吃」。
> 菜名里没写出来的成分它也认得：「小笼包」是猪肉馅，忌猪肉的人那一行会亮起来。
> 排过的桌留着，点一下就把那一桌的菜单拿回来重排。
>
> 言笺 · 说过的话落成笺
> 把聊天记录贴进来，笺把里面的待办、要买、已定、还没说清的四类话捞出来，
> 带上「明天 / 这周四 / 大后天」这类时间，谁说的也标出来。
> 分批贴不会互相冲掉，勾掉的会记住，想只看还没办的，按一下就行。
> 类别是猜的，猜错了点一下「挪」就换一类；日期也是猜的，点「时间」挑一天，
> 或者选「明天 / 后天 / 下周一」。猜错的日期比猜错的类别更看不见——类别错了就在屏幕上，
> 日期过了什么都不发生——所以两样都改得动，也都给一次反悔。
>
> 关于数据
> 所有东西都存在你自己手机里：没有账号，没有服务器，不联网也能用（离线可用是测过的）。
> 应用**不接入系统自动备份**（`allowBackup=false`），所以卸载即清除，不会被悄悄搬进云端；
> 要迁移或留存请用「册 → 导出备份」，那是你自己动手的一份文件。
> 「册」里可以导出备份、导入备份，也可以一键清空；这两下都是整体换掉本机数据，
> 所以每一次都先做、再给一次反悔——开机那句话会报清楚换进来多少件、多少条。
> 换机或导入时对不上形状的条目不会被带进界面，也不会悄悄少掉——它会说「少了几条」。
> 三张笺共用一个「笺点」钱包，模块可以随时开关（至少留一笺，全关掉就没有能去的笺了）。
> 发过的笺都存在「册」里，
> 点某一行就能把当时那整张笺再复制一次。
>
> 长按桌面图标可以直接进「过一件衣 / 排一桌菜 / 捞一段话 / 看今天 / 记一笔」，不用先从首页找。

> （会先在手机里缩小再发）会发往**你填的那个地址**；我们不代理、不留存、也不知道那个地址是什么。

## 3. 数据安全表（逐项结论）

判定依据：`aapt2 dump badging` 实测 release 包一共声明六条权限 ——
`android.permission.INTERNET`（仅在用户自行填写模型接口时才会用到）与
`android.permission.VIBRATE`（触感反馈，不读不写任何数据；由 @capacitor/haptics 带入）。
0.6.0 起多了「到点提醒」那一组，全部由 @capacitor/local-notifications 带入：
`android.permission.POST_NOTIFICATIONS`（安卓 13+ 的运行时权限，只在用户自己给某条言笺定了提醒、
第一次排通知时才会被问到；拒绝之后应用照常可用，只是不弹通知）、
`android.permission.RECEIVE_BOOT_COMPLETED` 与 `android.permission.WAKE_LOCK`
（重开机后把用户已经排好的提醒重新排上；都只系统自用，不读不写任何数据）。
另有 AndroidX 自动加的 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`（应用私有，Play 不计入敏感权限）。
没有相机、麦克风、通讯录、位置、存储类权限。前端是纯静态 H5，没有任何埋点、崩溃上报、
广告 SDK、分析 SDK；`engine.js` 是本地规则引擎；日常状态落在 WebView 的 `localStorage`，本机恢复点另存于 `IndexedDB`
与（原生壳里的）`@capacitor/preferences`，两者都是应用私有目录。

**刻意没申请的一条**：`SCHEDULE_EXACT_ALARM`（精确闹钟）。@capacitor/local-notifications 自己的清单
会带它进来，本项目用 `tools:node="remove"` 在合并时摘掉了——它在 Play 上属于受限权限，要单独
填声明表，而笺的提醒只承诺「大约这个点」（Doze 下本来就会被推迟几分钟）。摘掉之后插件自动退回
非精确闹钟，行为正是文案承诺的那一种；`aapt2 dump badging` 的六条里确实没有它。

| Play 的问题 | 该选 | 依据 |
|---|---|---|
| 是否与第三方共享数据？ | 否 | 代码里没有任何第三方 SDK；`grep` 可得：无 analytics / ad / crash 依赖 |
| 是否收集用户数据？ | 否（不收集） | 全部数据由用户在本机产生并只存在本机；App 不上传 |
| 数据是否加密传输？ | 默认「不适用」；一旦用户自填接口，这一栏要按**否**如实勾 | 应用自己不发起任何网络请求；但安卓壳刻意放行了明文流量（见下），所以用户填 `http://` 时那一次请求不加密，填 `https://` 才加密 |
| 数据可否删除？ | 是 | 「册 → 清空本地数据」一键清空，且带一次反悔 |
| 是否需要账号？ | 否 | 无账号体系 |
| 位置 / 联系人 / 相机 / 麦克风权限 | 不申请 | 照片走系统图片选择器（Photo Picker，无需存储权限）；唯一的运行时权限是通知（只在用户自己给言笺定了提醒时才会被问到） |
| 儿童内容 / 广告 | 无广告、非面向儿童 | 见清单 |

**两条要如实说明的**（都不是我们收集数据，但瞒不住审查，也不该瞒）：
1. 可选的「模型接口」由用户自己填写地址，一旦填写，用户贴进笺的文字、以及他主动拍/选的那张照片
   会发往那个地址。**照片在离开设备前先在机器里缩小**（实测认衣服那张最长边 ≤512 像素、
   抄截图那张 ≤768 像素，由 `test/e2e.playwright.py` 第 29 节量网关真收到的那张图钉着）。
2. 安卓壳刻意允许了明文流量（`res/xml/network_security_config.xml`）。原因是这条功能的常态就是
   用户自己家里那台机器上的 `http://192.168.x.x:8787`，而 targetSdk 28+ 默认禁明文——不放行，
   这个可选功能在安卓上就是死的（实测：不放行时设备上只剩「网关连不上：Failed to fetch」）。
   代价是用户填 `http://` 时那一次传输不加密，隐私政策里已按这个口径写（第 4 节）。
   除这一条出网路径之外，App 不含任何第三方请求。

**这一份已经发出去了，不是待办**：`https://tbj0623.github.io/jian-privacy/`。
源就是仓库里的 `docs/上架/privacy/index.html`，发布与核对都用 `scripts/publish-privacy.py`：

- `py scripts/publish-privacy.py` —— 把源逐字节推到 GitHub Pages。走 `gh` 的 Contents API 而不是
  `git push`：这台机器的 GitHub 被本地加速器接管（hosts 指到 127.0.0.1，证书是它自己签的），
  `gh` 认那张证书、`curl` 不认——少一条要修的传输链路就少一处会假失败的地方。
- `py scripts/publish-privacy.py --check` —— 比「GitHub 上那一份的 git blob == 本地这一份」，
  再实抓一次公开 URL**逐字节**比（实测：改完源没等构建，它会连着六次报「200 但不是这一份」，
  第七次才认——以前这里只判标题里那几个字，Pages 发着旧构建也照样报「live ok」）。
  这一条已经挂成一档门禁：`npm run test:ship`，它还顺带把公开那一页**渲染**出来量
  （`test/privacy_page.playwright.py`：360 宽不横向出血、落款滚得到、印章不变形、
  控制台一句报错都没有、并且真的一个站外请求都不发）。它要联网、要 `gh` 登录态，
  所以单列一档，不塞进每次跑的 fast（在没登录的机器上它该红得有意义，而不是把快门拖成一次网络投票）。

上面那块正文与那一页的话由 `test/store_claims.py` **逐句两头对**：标题、首句、九条条款、
联系方式、更新日期一共 13 条，两边任意一边单独改都会红。第 1 节那一格填的邮箱、第 4 节正文里
的邮箱、那一页上的邮箱，三处也必须是同一个。

- **内容分级**：Everyone。理由：无暴力/性/赌博/毒品内容；言笺允许用户粘贴自己的聊天文本，
